# Q&A 条目格式规范

每个分类文件（或子分类文件）是若干 Q&A 条目的集合。仅在写入条目时按需加载本文件。

## 文件头

每个分类/子分类文件以一级标题开头，简述涵盖范围：

```markdown
# <分类名>

> 涵盖：一句话说明这个分类收集哪些主题。
```

## 单条 Q&A 格式

每条 Q&A 使用二级标题作为问题，正文给出答案，并在末尾附元信息：

```markdown
## Q: <一句话问题>

<答案正文。可包含代码块、列表、链接。>

- 标签: `tag1`, `tag2`
- 记录于: YYYY-MM-DD
```

## 约定

- **问题用 `## Q:` 开头**，便于全文检索和在索引中引用锚点。
- 答案力求自包含：直接给结论，必要时补充代码示例与原因。
- `标签` 用于跨分类检索，可选但推荐。
- `记录于` 使用当前日期，便于追踪知识新鲜度。
- 同一文件内的条目按主题就近排列，相关条目相邻放置。
- 避免重复条目；若新问题与已有条目高度重合，更新已有条目而非新增。

## 示例

```markdown
# Git

> 涵盖：Git 版本控制的常用命令、工作流与排错。

## Q: 如何撤销最近一次还未推送的提交但保留改动？

使用软重置：

​```bash
git reset --soft HEAD~1
​```

改动会回到暂存区，提交记录被移除。若想同时清空暂存区用 `--mixed`（默认），
彻底丢弃改动用 `--hard`（慎用）。

- 标签: `git`, `undo`
- 记录于: 2026-06-18
```
