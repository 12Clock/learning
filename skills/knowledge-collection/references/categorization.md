# 分类与细分规则

本文件描述如何对问答进行分类，以及当某一分类条目过多时如何细分。仅在执行分类/细分时按需加载。

## 分类原则

- **按主题归类**，而非按时间。优先复用 `INDEX.md` 中已存在的分类。
- 分类名使用简洁的领域词，文件名用小写 + 连字符（如 `python.md`、`git.md`、`system-design.md`）。
- 一条 Q&A 只归入一个最贴切的分类；若确实跨多类，归入主分类并在内容中交叉引用。
- 拿不准归类时，先放入最接近的分类，不要凭空制造大量空分类。

## 目录与文件结构

```
knowledge/
  INDEX.md                  # 总索引（必读路由表）
  python.md                 # 单文件分类
  git.md
  databases/                # 已细分的分类 → 升级为目录
    INDEX.md                # 子索引
    sql-optimization.md
    indexing.md
```

- 分类初始为单个 `<category>.md` 文件。
- 当需要细分时，将其升级为同名**目录**，目录内含一个子 `INDEX.md` 和多个子分类文件。

## 细分触发阈值

满足任一条件时，考虑对该分类细分：

- 单个分类文件中的 Q&A 条目 **超过 15 条**；或
- 文件长度 **超过约 400 行**；或
- 该分类内已自然形成 2 个以上明显子主题（即使条目未达阈值）。

阈值是参考值而非硬性规则——以"读者能否快速定位"为最终判断标准。

## 细分步骤

1. 通读该分类下的全部 Q&A，归纳出 2–5 个子主题。
2. 把单文件 `<category>.md` 改为目录 `<category>/`。
3. 在目录内为每个子主题创建 `<subtopic>.md`，把对应 Q&A 迁移过去（保持格式不变）。
4. 在 `<category>/INDEX.md` 中列出各子文件及其涵盖范围。
5. 更新顶层 `knowledge/INDEX.md`：把原来的单文件条目替换为指向该分类目录及其子索引。
6. 迁移后不要遗留重复内容；确认原单文件已被目录取代。

## 反向操作

若某细分子主题长期只有极少条目且无增长趋势，可在细分时将其合并回相邻子主题，避免碎片化。
